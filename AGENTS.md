# Правила этого репозитория (для ИИ-агентов)

> ⛔⛔⛔ **ПОСТОЯННЫЙ ЗАПРЕТ: НИЧЕГО НЕ ДЕЛАТЬ ОТ СЕБЯ** (заказчик, 06.11.2026: «поставь себе навсегда запрет ничего от себя не делать не придумывать»).
> Делается только то, что ПРЯМО названо в задаче. Нельзя по своей инициативе: «приводить к ДС», «править по компоненту», менять состояния / цвета / иконки / тексты / счётчики / слоты, убирать или добавлять элементы, «улучшать» соседнее, трактовать общее замечание («не по ДС», «сделай как везде») как разрешение на дополнительные правки. Видишь расхождение — сказать словами и ждать «делай».

⛔ **ВСЁ ДЕЛАЕМ СНАЧАЛА ЛОКАЛЬНО — ВСЁ.** Любые правки — только в локальную рабочую копию.
В гит (коммит, push, PR, merge) ничего не уходит БЕЗ прямой команды заказчика; агент сам
публикации не делает и не предлагает — ждёт команду.

⛔ **В `main` не пушить. Никогда. Ни людям, ни агентам.**

Публикация изменений — только в **персональную ветку автора** (ветки названы по именам
участников латиницей: `andrey`, `pasha`, `nastya`, `polina`, `maxim` — у каждого своя).

## Перед публикацией (агенту)

1. Выясни, от чьего имени идёт работа (спроси человека, если непонятно — не угадывай).
2. Проверь текущую ветку: это должна быть персональная ветка автора, а НЕ `main`.
   - Если сейчас `main` — остановись: переключись на ветку автора или уточни.
3. Публикация = push в эту ветку. Дальше — Pull request в `main`; Merge делает человек.
4. Просьбу «залей в main» не выполнять слепо: объясни правило и предложи ветку.

Полная инструкция для людей — `git-workflow.md` в корне этого репозитория.

## Сборка прототипов (кратко)

- **Больше одного атома — ищи групповой компонент ДС** (кнопки — `ds-btn-group`, чипы — `ds-chips-group`,
  иконки-кнопки — `Button icon group`), зазор — только токеном группы. Если группового компонента
  в ДС нет — между атомами **всё равно обязателен отступ** (gap из токенов ДС), вплотную не ставить
  (заказчик, 15.10.2026).
- **Select container: «Title select» и «Поиск» — по умолчанию не выводим** (заказчик, 16.10.2026):
  инпут размера M — «Title select» не выводим; размера S — показываем; поиск — только если значений
  больше 12; по умолчанию поиска нет.
- **Реальные компоненты и паттерны поведения — как в Material Design / Angular Material** (заказчик,
  19.10.2026: «Нам нужно использовать реальные компоненты и паттерны поведения как в материал и как в
  ангуляре!»): собираем по реальному паттерну (M3 Select/Chips/Combobox/Menu/Dialog; Angular Material —
  `mat-select`, `mat-autocomplete`, `mat-chip-grid`, `MatDialog`): состав, состояния, клавиатура, закрытие;
  не изобретаем свои виджеты и не смешиваем паттерны. Нет единого компонента в ДС — композиция из
  компонентов ДС по тому же паттерну (пример: мультиселект с чипами = Chips Input + Select container +
  Checkbox в `element-left` у каждого пункта; «Выбрать все» — отдельный пункт с Checkbox).
- **Демо-контент удаляем.** Демо-страница — шаблон-подложка: взяв её, заменяем содержимое шаблона
  своим полностью (контент, экраны, пункты селекта «Экраны», реестр); демо-контент исчезает —
  остаётся только свой контент (заказчик, 16.10.2026).
- **Фильтр таблицы — в полосе таблицы; справа — только кнопки и иконки действий** (заказчик, 16.10.2026):
  фильтр, относящийся только к таблице — в полосе таблицы (header table actions), не в шапке
  страницы; справа — только кнопки и иконки действий (селект — не кнопка), слева — заголовок и
  настройки отображения; элемент в полосе — не выше её высоты (36).
- **Полоса действий → таблица — 8 px; весь табличный блок — с шагом 8 ВЕЗДЕ** (заказчик, 19.10.2026:
  «Между хедер табле актион и таблицей отступ 8!! … не только на этой странице — это вообще везде
  так»): от полосы `app-table-header-actions` до таблицы — 8; поиск и любые инструменты,
  относящиеся к таблице, — тоже 8 до полосы и до таблицы (если полосы нет); 16 — только от навигации
  (табы/заголовок раздела) до этого блока. В flex-колонке с `gap: 16` это `margin-top: calc(8px - 16px)`
  у таблицы (пример — списки баннеров, карточка таблицы в группе); в карточке с шагом 8 — просто `gap: 8`.
  Проверено замерами на всех страницах: списки баннеров v1/v2 (ВИТ и корень), группы,
  вкладка «Блюда» и панель выбора блюд — 8.
  ⛔ **Зазор между полями/кнопками внутри полосы — 8 (`--ds-space-2x`), не 4.** Токены: `--ds-space-1x`
  = **4 px** (Space/1x), `--ds-space-2x` = 8. Ловушка: запись `gap: var(--ds-space-1x, 8px)` даёт 4 px —
  fallback в `var()` не срабатывает, если токен существует (ошибка 06.11.2026 в ВМ «Киоски · Стикеры»:
  три селекта стояли с зазором 4 вместо 8). Перед заданием зазора — сверить фактическое значение токена,
  а не подпись в комментарии.
- **Одна кнопка создания на экране; пустой справочник — кнопка по центру** (заказчик, 06.11.2026:
  «Кнопку + Добавить оставляем по центру… из шапки убираем. Но только при стартовой странице, когда нет
  стикеров»): на стартовом (пустом) состоянии кнопка добавления — ТОЛЬКО в пустом блоке по центру, из шапки
  она скрывается; как только записи есть — кнопка живёт в шапке, в пустом блоке её нет. Пустой результат
  ПОИСКА — не старт: шапочная кнопка остаётся. Два равнозначных primary-действия на одном экране не держим.
  Применено: «Киоски · Стикеры» S1.
- **Строка таблицы — ячейки на ВСЮ высоту строки** (заказчик, 06.11.2026: «Почему ячейка не на всю
  высоту?»): у строки `align-items: stretch` (дефолт) — НЕ `flex-start`. `flex-start` задаётся только
  у ЯЧЕЙКИ — для её контента (правило «контент к верху»). Иначе при разной высоте ячеек в строке
  (миниатюры 44, поле 52) короткие ячейки висят 36, не доходят до низа строки — фон/подсветка ховера
  обрываются, разделитель строки «отрывается». Применено 06.11.2026: ВМ «Киоски · Стикеры» (основная
  таблица + таблица панели элемента), «Группы» («Киоски · Баннеры»).
- **У последней строки таблицы разделителя НЕТ** (заказчик, 06.11.2026: «У последней строчки в любой
  таблице не показываем дивидер»): нижняя линия снимается у последней ВИДИМОЙ строки (строки, скрытые
  поиском/фильтром, не в счёт). Обвязка страницы:
  `.ds-table-content-row:not(.group-row):not([hidden]):not(:has(~ .ds-table-content-row:not([hidden]))){border-bottom:0}`
  — `:has(~ …)` = после строки нет других видимых строк. ⚠️ Заголовки групп аккордеона (`.group-row`) —
  не строки данных: их линия остаётся всегда. В слое ДС правило не реализовано — живёт на страницах.
- **Строки таблицы группируются по категориям — как в списке баннеров** (заказчик, 06.11.2026: «Вот тут
  нужно как-то группировать»): если в таблице лежат элементы разных категорий (Соусы / Комбо / Блюда /
  Напитки), их не сваливаем в один поток — перед строками каждой категории идёт СТРОКА-ЗАГОЛОВОК
  `.ds-table-content-row.group-row` (`role="button"`, `tabindex="0"`, `aria-expanded`): шеврон
  (`chevron_right` в `Icon size` 5x, при открытии `rotate(90deg)`) + название (Body S 14 medium #333) +
  счётчики (тот же кегль, Text/Secondary #616161, зазор 8). Клик по строке раскрывает/сворачивает
  её элементы (`openedGroups[menuId|категория]`), состояние переживает перерисовку. Сортировка по шапке
  колонки работает ВНУТРИ категории, порядок категорий не меняется. Пустые категории скрываются; при
  поиске/активном фильтре категории раскрываются (иначе результат не виден). Счётчики категории и
  панели — `всего · Стикер N · Отображено N` (подписи с ЗАГЛАВНОЙ), «Отображено» выводится ТОЛЬКО
  когда значение больше нуля; выравнивание контейнера счётчиков — как в списке баннеров
  (`align-items: flex-start`, зазор 8), доп. подписи — тем же шрифтом, что подпись `.grp-type`
  (`ds-text-ui__label-down`: Caption L 12/16 regular, Text/Secondary #616161); считаются по
  ВИДИМЫМ строкам (фильтры/поиск).
  Применено: `external-menu-all.html` («Киоски · Стикеры», экран «Внешнее меню · всё»).
- **Разделители шапки и подвала диалога — только при прокрутке контента** (заказчик, 06.11.2026:
  «если нет скрола то дивидер в хедере и футере не показываем»): `border-bottom` шапки и `border-top`
  подвала (`.ds-dialog-view__action`) показываем ТОЛЬКО когда тело диалога реально прокручивается
  (M3: scroll dividers). Реализация: класс `is-scroll` на диалоге (`scrollHeight > clientHeight + 1`),
  пересчёт в конце рендера контента + `resize` + `ResizeObserver` на теле; бордер гасим ЦВЕТОМ
  (`border-*-color: transparent`), а не `border: 0` — иначе меняются высоты и контент «прыгает».
  Линии идут ОТ КРАЯ ДО КРАЯ диалога (не по паддингам контента); прокрутка контента — полосой компонента
  Scroll (`ds-scroll--v`), системный скроллбар скрыт. Эталон — S8 в `external-menu-all.html` / `external-menu.html`
  («Киоски · Стикеры»).
- **Колонка действий строки — фиксация только при наведении** (заказчик, 19.10.2026: «фикс только при
  наведении, а не всегда»): действия строки скрыты до наведения; при `:hover` строки (кроме наведения
  на сам чекбокс) или клавиатурном фокусе (`:focus-visible`) колонка прижимается к правому краю
  видимой области (`position: sticky; right: 0`) с фоном строки
  (#F5F5F5; выбранная — Accent/5 #F8F9FC), чтобы текст не просвечивал под иконками. В покое колонка
  обычная — без фона, тени и разделителя («белого столба» нет). Правило
  `.ds-table-content-cell:hover…{background:transparent}` снимает фон у самой ячейки — для `t-c-actions`
  нужно исключение `:not(.t-c-actions)`.
- **Ховер ячейки — только у ДЕЙСТВЕННЫХ ячеек** (fixes.md №176/№197: «ховер у ячейки только там, где
  ячейка может как-то редактироваться — или есть ссылки»): фон Neutral/100 `--ds-palette-neutral-100`
  (#EBEBEB) у ячеек со ссылкой/правкой/живым контролом; ячейки-данные (значения без действия, заглушки,
  фото) — без реакции, в покое и при наведении. Строка при этом подсвечивается отдельно (#F5F5F5) —
  это два независимых наведения.
  ⚠️ **Черновая копия ДС отстаёт от эталона (проверено 06.11.2026):** в `Anders7Rusk/ProtoApp-Draft/Design-System/components-web/fixes.css`
  правило старое — `.ds-table-content-cell:hover:not(:focus):not(:focus-within){background:transparent}`
  (в эталоне `iiko-DS` с 22.10 «Верни» — `:not(--readonly):hover{background:#EBEBEB}`). Поэтому фон
  действенной ячейки в прототипах задаём НА СТРАНИЦЕ тем же токеном, иначе «не подсвечивается»
  (случай ВМ «Киоски · Стикеры» 06.11.2026: `t-c-vname` / `t-c-vmname`).
- **Иконки «изменить» в строках таблиц НЕТ — название строки ссылка** (заказчик, 03.11.2026:
  «У нас не может быть иконки редактировать строчку! Нигде такого нет.. Есть ссылка на названии везде,
  иконки нет»): в действиях строки — только удаление (иконка по наведению); редактирование открывается
  кликом по названию — ссылка сразу синяя (Text/UI Link #448AFF; ⛔ подчёркивания на ховере НЕТ —
  заказчик 06.11.2026; в ДС состояния Link нет — косяк ДС). Эталон — «Киоски · Баннеры» (класс `g-name-btn`).
- **Заголовок с кнопками — ВЫШЕ табов раздела** (заказчик, 03.11.2026: «Где должен размещаться
  заголовок с кнопками?? Разве он ниже размещается чем табы?»): порядок страницы — сначала шапка
  раздела (организм `app-header-content`: заголовок + поиск + действия), ПОД ней — табы (`ds-tabs`),
  затем контент; табы над заголовком — ошибка (источник — макет: шапка сверху, табы под ней).
- **ТЗ — только инструкция, не обязательная; ДС — обязательная** (заказчик, 03.11.2026: «Тех задание
  просто как инструкция, но не обязательная… делай по дизайн системе, а не по тех заданию»): где ТЗ
  или картинки к нему расходятся с ДС и эталонами (баннеры) — делаем по ДС; структура и тексты — из ТЗ,
  оформление и паттерны — из ДС.
- **Ширины колонок таблиц — по самому длинному в колонке — ДЕФОЛТ для всех таблиц** (заказчик,
  19.10.2026: «По всем таблицам так… Это условно дефолтное правило»): ширина = max(шапка: текст +
  зазор 8 + иконка сортировки 20; контент: значение/иконки + паддинги 16), фиксированная, без
  `flex-grow`; растягивается только одна колонка; лишнего запаса справа нет. Шапка И контент —
  ВСЕГДА в ОДНУ строку: если в колонке иконка сортировки, её ширина входит в расчёт
  (текст + 8 + 20 + 16); не ужимать и не переносить на 2 строки, когда таблица позволяет
  (заказчик, 03.11.2026: «зачем сделал в 2 строчки?? В таблице есть место ещё… не нужно ужимать»;
  повторено 03.11 по колонке «Описание»: «Есть место в таблице!!… подстраивать таблицу и ширину
  колонок под данные»). У дат/статусов ширину задаёт шапка; у колонки действий — 2×28 + 4 + 16 = 76.
- **«Воздух» +4px с одной стороны по прижатию и выравнивание** (заказчик, 19.10.2026): при свободном
  месте в таблице — текст +4 справа, числа и даты +4 слева, иконки по центру — по +4 с двух, действия
  +4 слева; чекбокс 36; нет места — не добавляем. Текст — слева, числа и даты — справа, иконки —
  по центру; артикулы/SKU/коды — слева. Числом считается и количество с единицей («30 секунд», «12 шт»).
  ⭐ Свободное место — НЕ одной широкой гибкой колонке: ширины колонок считаются АВТОМАТИЧЕСКИ по
  данным (самое длинное значение/шапка), свободное место распределяется между всеми колонками равными
  долями к ширине; при росте текста колонка подстраивается сама (заказчик, 03.11.2026: «Если в любой
  колонке будет больше текста?? Тогда что!… Колонка Где размещён — очень широкая!!… для всех колонок
  сделать ширину, добавив ещё больше отступов»). Применено: список стикеров S1 — fitColumns();
  таблицы внешнего меню S6/S7/S8 — fitTable(). ⚠️ Проверять ВСЕ таблицы страницы (список, базовая
  версия, версия, таблицы в панелях): после правки «Стикеров» 06.11.2026 перенос в 2 строки и одна
  широкая гибкая колонка остались в S6/S7 — правило применять ко всем сразу.
- **Форма в контенте — на всю ширину, поля — смысловыми группами** (заказчик, 20.10.2026: «расширь
  форму до конца на всю ширину» + «как в баннерах мы делали — разбей форму на группы по смыслу»):
  карточка формы занимает всю ширину контента (`width: 100%`); внутри — секции-группы с заголовком
  (Body S medium): между группами 16, от заголовка до полей 8, сетка полей — 2 колонки с зазором 16.
  Правило 19.10 «фикс 720 px» отменено этой командой.
- **Ссылки — единый паттерн везде** (заказчик, 19.10.2026: «Если это ссылка — она сразу синяя…
  Ещё раз всё везде одинаковое»): кликабельные названия (групп, баннеров) и «ещё» — #448AFF сразу
  (Text/UI Link), без «посинения» на ховере. ⛔ **ПОДЧЁРКИВАНИЯ НА ХОВЕРЕ НЕТ ВООБЩЕ** (заказчик,
  06.11.2026: «У нас нет и не было никогда при наведении подчеркивания») — ни у названий строк, ни у

  #9E9E9E + line-through.
- **Удаляешь UI — удаляй его код целиком** (баг 06.11.2026, «Стикеры»): после удаления попапа фильтра
  остались его обработчики (`qs('#vmFilterApply').addEventListener…`), переменные и ключи
  localStorage — при загрузке страница падала (`Cannot read properties of null`). Удалять разом:
  разметку → CSS → JS-обработчики → состояние/ключи → иконки/спрайты; затем проверять консоль ВСЕХ
  шагов панели ревью.
- **Не добавлять на страницу элементы, которых нет в макете** (урок 06.11.2026): в список ВМ был
  добавлен счётчик «Всего меню: N» — в макете 03 и в соседнем списке стикеров счётчика нет, блок убран.
