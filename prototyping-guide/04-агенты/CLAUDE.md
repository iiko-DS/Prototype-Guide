# Правила для Claude Code

> ⛔⛔⛔ **ПОСТОЯННЫЙ ЗАПРЕТ: НИЧЕГО НЕ ДЕЛАТЬ ОТ СЕБЯ** (заказчик, 06.11.2026: «поставь себе навсегда запрет ничего от себя не делать не придумывать»).
> Делается только то, что ПРЯМО названо в задаче. Нельзя по своей инициативе: «приводить к ДС», «править по компоненту», менять состояния / цвета / иконки / тексты / счётчики / слоты, убирать или добавлять элементы, «улучшать» соседнее, трактовать общее замечание («не по ДС», «сделай как везде») как разрешение на дополнительные правки. Видишь расхождение — сказать словами и ждать «делай».

Работая с дизайн-системой iiko, следуй правилам из [`AGENTS.md`](AGENTS.md) — это основной документ, здесь только самое важное:

- Интерфейс собирается **только** из компонентов ДС: классы `ds-*` и токены `--ds-*`. Самодельные стили запрещены, кроме обвязки раскладки.
- Макет задаёт структуру и тексты, ДС — внешний вид. Стили макета на компоненты не переносим.
- Правка поверх компонента — только при реальном пробеле ДС, с комментарием `/* косяк ДС: … */`.
- Перед сборкой блока читать `components-web/iiko-ds-spec.md`.
- 2+ однотипных элемента — групповой компонент ДС (кнопки — `ds-btn-group`, чипы — `ds-chips-group`), зазор — токеном группы; если группового компонента нет — между элементами всё равно обязателен отступ.
- Select container: «Title select» и «Поиск» — по умолчанию не выводим: инпут размера M — «Title select» не выводим, размера S — показываем; поиск — только если значений больше 12 (заказчик, 16.10.2026).
- **Реальные компоненты и паттерны поведения — как в Material Design / Angular Material** (заказчик, 19.10.2026): контрол собираем по реальному паттерну (`mat-select`/`mat-select multiple`, `mat-autocomplete`, `mat-chip-grid`, `MatDialog`): состав, состояния, клавиатура, закрытие; визуал/токены — из ДС; нет единого компонента в ДС — композиция из компонентов ДС по тому же паттерну (мультиселект с чипами = Chips Input + Select container + Checkbox у каждого пункта; «Выбрать все» — отдельный пункт с Checkbox).
- Демо-страница — шаблон-подложка: взяв её, заменяем её содержимое своим и удаляем демо-контент (в прототипе остаётся только свой контент).
- Фильтр таблицы — в полосе таблицы (header table actions), не в шапке страницы; справа в полосе — только кнопки и иконки действий (селект — не кнопка; элемент не выше высоты полосы — 36).
- Иконки «изменить» в строках таблиц нет — название строки ссылка (сразу #448AFF, без подчёркивания на ховере — заказчик 06.11.2026); в действиях строки — только удаление по наведению. Эталон — списки баннеров, класс `g-name-btn` (заказчик, 03.11.2026).
- У последней строки таблицы разделителя нет (заказчик, 06.11.2026): нижняя линия снимается у последней ВИДИМОЙ строки (скрытые поиском/фильтром не в счёт); заголовки групп аккордеона (`.group-row`) — не строки данных, их линия остаётся. Обвязка страницы: `.ds-table-content-row:not(.group-row):not([hidden]):not(:has(~ .ds-table-content-row:not([hidden]))){border-bottom:0}`.
- Разделители шапки и подвала диалога — ТОЛЬКО когда контент прокручивается (заказчик, 06.11.2026: «если нет скрола то дивидер в хедере и футере не показываем»): класс `is-scroll` на диалоге (`scrollHeight > clientHeight + 1`) + `border-*-color: transparent` у шапки/подвала (не `border: 0` — иначе высоты «прыгают»); пересчёт после рендера, на `resize` и через `ResizeObserver`.
- Заголовок с кнопками — ВЫШЕ табов раздела: сначала `app-header-content` (заголовок + поиск + действия), под ним — `ds-tabs`, затем контент (заказчик, 03.11.2026).
- ТЗ — только инструкция, не обязательная: где ТЗ/картинки расходятся с ДС и эталонами — делаем по ДС; структура и тексты — из ТЗ, оформление и паттерны — из ДС (заказчик, 03.11.2026).
- Всё, что есть в примере, работает: диалог открывается/закрывается (крестик, Esc, кнопка, клик по затемнению), скролл прокручивается, ползунок Scroll перетаскивается (заказчик, 19.10.2026).
- Для всех демо-страниц компонентов — обязательно смотреть слои и настройки в Figma (дерево слоёв + Properties: вариант/размер/состояние/слоты/вложенные инстансы/скрытые слои); вложенные инстансы собираем компонентами ДС, не голыми svg (заказчик, 19.10.2026).
- В `main` не коммитить: ветка `имя/что-делаю` → Pull Request.

Подробности и таблица «где что лежит» — в `AGENTS.md`. Глубокие знания по системе — в скиллах `skills/iiko-ds-components/` и `skills/iiko-design-system/`.
