# Правила работы с дизайн-системой iiko

> ⛔⛔⛔ **ПОСТОЯННЫЙ ЗАПРЕТ: НИЧЕГО НЕ ДЕЛАТЬ ОТ СЕБЯ** (заказчик, 06.11.2026: «поставь себе навсегда запрет ничего от себя не делать не придумывать»).
> Делается только то, что ПРЯМО названо в задаче. Нельзя по своей инициативе: «приводить к ДС», «править по компоненту», менять состояния / цвета / иконки / тексты / счётчики / слоты, убирать или добавлять элементы, «улучшать» соседнее, трактовать общее замечание («не по ДС», «сделай как везде») как разрешение на дополнительные правки. Видишь расхождение — сказать словами и ждать «делай».

Файл для ИИ-агентов: читать перед любой работой с компонентами, прототипами и значениями ДС.

## Главное

- **Интерфейс собирается только из компонентов ДС.** Готовые классы `ds-*` из `components-web/components/<Имя>_DS/*.css` (общий индекс — `components/index.css`) и токены `--ds-*` из `components-web/tokens.css`.
- **Макет (Figma) задаёт структуру и тексты. Внешний вид задаёт ДС.** Стили макета на компоненты не переносим: капс, цвета, трекинги, радиусы, внутренние паддинги и размеры — у компонента свои токены и состояния.
- **Самодельные классы запрещены.** Допустимо только: обвязка раскладки (позиционирование, ширины колонок, гэпы контекста); правка поверх ДС — только при реальном пробеле системы и с комментарием в коде `/* косяк ДС: … */`; новый компонент — только если такого в ДС нет, с пометкой.
- **Настройка компонента — через его переменные** (`--ds-…`), а не переписыванием стилей.
- **Реальные компоненты и паттерны поведения — как в Material Design / Angular Material** (заказчик,
  19.10.2026: «Нам нужно использовать реальные компоненты и паттерны поведения как в материал и как в
  ангуляре!»): любой контрол/сценарий — по реальному паттерну (M3: Select, Chips, Combobox, Menu, Dialog;
  Angular Material: `mat-select`, `mat-autocomplete`, `mat-chip-grid`, `MatDialog`…): состав, состояния,
  клавиатура, закрытие — как у настоящего компонента. Визуал/токены — из ДС, Material/Angular — источник
  паттернов поведения. Нет единого компонента в ДС — композиция из компонентов ДС по тому же паттерну,
  без гибридов (пример: мультиселект с чипами = Chips Input + Select container + Checkbox в `element-left`
  у каждого пункта; «Выбрать все» — отдельный пункт с Checkbox и indeterminate).
- **Ширина — по блоку.** Каждый компонент растягивается по ширине блока, в котором стоит (колонка формы, карточка, панель): ширину задаёт раскладка, а не содержимое компонента.
- **Форма в контенте — на всю ширину, поля — смысловыми группами** (заказчик, 20.10.2026: «расширь форму до конца на всю ширину» + «как в баннерах мы делали — разбей форму на группы по смыслу»): карточка формы — на всю ширину контента; внутри — секции-группы с заголовком, между группами 16, от заголовка до полей 8, сетка полей — 2 колонки с зазором 16 (правило 19.10 «фикс 720 px» отменено).
- **Демо-контент удаляем — остаётся только свой.** Демо-страница — шаблон-подложка: взяв её, заменяем всё её содержимое своим (контент, экраны, пункты селекта «Экраны», реестр панели), демо-контент удаляется и в готовом прототипе не остаётся (заказчик, 16.10.2026).
- **Фильтр таблицы — в полосе таблицы; справа в полосе — только кнопки и иконки действий (заказчик, 16.10.2026).** (1) Если фильтр относится только к тому, что происходит в таблице (а не к странице в целом) — он размещается В ПОЛОСЕ ТАБЛИЦЫ (header table actions), не в шапке страницы. (2) В полосе таблицы размещаются СПРАВА: «все кнопки действий в header table actions размещаются справа»; слева — заголовок и настройки отображения (группировки, тумблеры). (3) Уточнение 16.10: справа — ТОЛЬКО кнопки и иконки действий («Справа только кнопки и иконки действий... Селект это не кнопка»). Размер элемента в полосе — не больше высоты полосы: организм 36 px («селект должен быть не больше высоты 36 пикс»); у Select form в ДС размеры M 48 / S 36 / XS 28 — в полосу берём S.
- **Колонка действий строки — фиксация только при наведении (заказчик, 19.10.2026).** Действия строки скрыты до наведения; при наведении строки (кроме наведения на сам чекбокс) или клавиатурном фокусе (`:focus-visible`) её колонка действий прижимается к правому краю видимой области (`position: sticky; right: 0`) с фоном строки (#F5F5F5; выбранная — Accent/5 #F8F9FC), чтобы текст не просвечивал под иконками. ⚠️ `:focus-within` от клика по чекбоксу действия НЕ показывает (заказчик, 09.11.2026). В покое колонка обычная — без фона, тени и разделителя («белого столба» нет); постоянный sticky/тень/линию не задавать. Правило `.ds-table-content-cell:hover…{background:transparent}` снимает фон у самой ячейки при наведении — для колонки действий нужно исключение `:not(.t-c-actions)`, иначе текст просвечивает сквозь иконки. Эталон — прототипы «Киоски · Баннеры» v1/v2 (журнал №206).
- **У последней строки таблицы разделителя НЕТ** (заказчик, 06.11.2026: «У последней строчки в любой таблице не показываем дивидер»): нижняя линия снимается у последней ВИДИМОЙ строки (скрытые поиском/фильтром строки не в счёт). Обвязка страницы: `.ds-table-content-row:not(.group-row):not([hidden]):not(:has(~ .ds-table-content-row:not([hidden]))){border-bottom:0}` — `:has(~ …)` = после строки нет других видимых. ⚠️ Заголовки групп аккордеона (`.group-row`) — не строки данных: их линия остаётся всегда. В ДС правило не реализовано — живёт на страницах.
- **Разделители шапки и подвала диалога — только при прокрутке контента** (заказчик, 06.11.2026: «если нет скрола то дивидер в хедере и футере не показываем»): `border-bottom` шапки и `border-top` подвала (`.ds-dialog-view__action`) — ТОЛЬКО когда тело диалога реально прокручивается (M3: scroll dividers); контент влезает — линий нет. Реализация: класс `is-scroll` на диалоге (`scrollHeight > clientHeight + 1`), пересчёт в конце рендера контента + `resize` + `ResizeObserver` на теле; бордер гасим ЦВЕТОМ (`border-*-color: transparent`), а не `border: 0` — иначе меняются высоты и контент «прыгает». Линии идут ОТ КРАЯ ДО КРАЯ диалога (не по паддингам контента); прокрутка контента — полосой компонента Scroll (`ds-scroll--v`), системный скроллбар скрыт. Эталон — S8 в `external-menu-all.html` / `external-menu.html` («Киоски · Стикеры»).
- **Состояние объекта в ячейке — бейдж-галочка на миниатюре** (заказчик, 06.11.2026: «Нужно в таблице как-то показать отображается стикер или нет… Кажется бейдж с зелёной галочкой пока самое правильное. Справа в верхнем углу»): если у объекта есть флаг, который задаётся в попапе (например, «Отображать на итоговой картинке комбо»), в таблице он показывается меткой — `ds-badge ds-badge--counter ds-badge--positive` (18×18, паддинг 1, radius circular) с `ds-icon-size--4x` + `check` белым, в правом верхнем углу миниатюры со смещением −4/−4; нет флага — метки нет (без «тире»). ⚠️ В ДС варианта Badge с иконкой нет — это пробел ДС №271, обход помечен в коде. Пример: колонка «Стикеры» в «Киоски · Стикеры».
- **Тултип (Hint) — центрируется по иконке-триггеру** (замечание 06.11.2026, «что за жесть с тултипом»: тултип был выровнен по правому краю иконки — хвостик уезжал на ~130 px влево и указывал не на иконку, а сам тултип перекрывал шапку таблицы): хвостик — ТОЧНО под иконкой (`left = centerX(иконки) − width/2`), отступ от иконки 8; если тултип не помещается у края экрана — зажим по 8 px и СМЕЩЕНИЕ ХВОСТИКА на иконку (`transform: translateX`), а не «прилипание» контейнера краем; тултип не перекрывает шапку таблицы (`top = max(icon.bottom + 8, headerRow.bottom + 4)`); элемент один на страницу `position: fixed`, прячется при скролле тела. Эталон — `#elHint` в `external-menu-all.html` / `external-menu.html`.
- **Иконки «изменить» в строках таблиц НЕТ — название строки ссылка** (заказчик, 03.11.2026: «У нас не может быть иконки редактировать строчку! Нигде такого нет.. Есть ссылка на названии везде, иконки нет»): в действиях строки — только удаление (иконка по наведению); редактирование — кликом по названию, ссылка сразу синяя (Text/UI Link #448AFF; ⛔ подчёркивания на ховере НЕТ — заказчик 06.11.2026: «У нас нет и не было никогда при наведении подчеркивания»; в ДС состояния Link нет — косяк ДС). Эталон — «Киоски · Баннеры» (класс `g-name-btn`).
- **Заголовок с кнопками — ВЫШЕ табов раздела** (заказчик, 03.11.2026: «Где должен размещаться заголовок с кнопками?? Разве он ниже размещается чем табы?»): сначала шапка раздела (`app-header-content`: заголовок + поиск + действия), ПОД ней — табы (`ds-tabs`), затем контент; табы над заголовком — ошибка.
- **ТЗ — только инструкция, не обязательная; ДС — обязательная** (заказчик, 03.11.2026: «Тех задание просто как инструкция, но не обязательная… делай по дизайн системе, а не по тех заданию»): где ТЗ/картинки расходятся с ДС и эталонами — делаем по ДС; структура и тексты — из ТЗ, оформление и паттерны — из ДС.
- **Иконки** — Material Icons по имени (`<span class="material-icons">search</span>`), семейство Outlined. Фирменные глифы — точной выгрузкой из макета, инлайн svg с `fill: currentColor`.
- **Для ВСЕХ демо-страниц компонентов — обязательно смотреть слои и настройки в Figma** (заказчик, 19.10.2026: «Ещё раз для всех демо страниц компонентов обязательно смотреть слои и настройки в фигме»): перед сборкой/правкой любой вкладки — дерево слоёв + Properties (вариант, размер, состояние, слоты, вложенные инстансы, скрытые слои); вложенные инстансы воспроизводятся компонентами ДС (Icon size, State), а не голыми svg.

## Проверка перед сдачей блока

1. В разметке — классы `ds-*` и слоты по спецификации, а не самодельные.
2. Внешний вид сверен со спецификацией; состояния Default / Hover / Press / Selected / Disable — из ДС.
3. Каждая правка поверх компонента — с комментарием, какой пробел ДС она закрывает.
4. **Больше одного атома → ищи групповой компонент ДС** (заказчик, 15.10.2026: «Если компонента-атома используется больше 1 шт — ищи групповой компонент. Если группового компонента нет, то всё равно должен быть отступ между компонентами»). 2+ однотипных элемента (кнопки, чипы, иконки-кнопки…) — сначала ищи в ДС групповой компонент: кнопки — `ds-btn-group` (`ds-btn-group--horizontal`; в футерах ещё `--margins`), чипы — `ds-chips-group`, иконки-кнопки — `Button icon group`; собирай через него, зазор — только токеном группы (`--ds-button-group-gap` и т. п.), свой `gap`/`margin` не задавать. Порядок кнопок: второстепенные слева, главная последняя справа. **Если группового компонента в ДС нет — между элементами всё равно обязателен отступ** (gap из токенов ДС), вплотную не ставить.
5. **Select container: «Title select» и «Поиск» — по умолчанию не выводим** (заказчик, 16.10.2026): инпут размера M — «Title select» не выводим; размера S — показываем; поиск — только если значений больше 12; по умолчанию поиска нет.
6. **Всё, что есть в примере, работает** (заказчик, 19.10.2026): диалог/панель открывается и закрывается (крестик, Esc, кнопка действия, клик по затемнению Backdrop); если есть скролл — контент реально прокручивается, ползунок Scroll перетаскивается и синхронизирован со scrollTop; контролы живые.

## Работа с репозиториями

- ⛔ **Сначала — локально (всегда).** Все правки делаются в рабочей копии; коммит, push, PR, merge —
  только по прямой команде заказчика. Агент сам публикации не делает и не предлагает.
- `main` — общая база: прямых коммитов в неё нет. Своя ветка (`имя/что-делаю`) → коммит → Pull Request.
- Описания коммитов и PR — по-русски и по делу: что изменилось и почему.
- Не коммитим: проверочные скриншоты и пробы, секреты (`.env`, `.vscode/mcp.json`).
