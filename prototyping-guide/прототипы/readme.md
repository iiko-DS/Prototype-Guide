# Прототипы

Всё про прототипы: что это у нас, где лежат, из чего собираются и как показываются. Как устроена сама система, из которой они собираются, — в [`../дизайн-система/`](../дизайн-система/).

## Что такое прототип у нас

Прототип — это **страница или стенд, который можно нажимать**: он показывает поведение (что происходит при клике, какие состояния, как меняется карточка), а не картинку «как это могло бы выглядеть». Он собирается из компонентов дизайн-системы, поэтому то, что на нём видно, совпадает с тем, что потом делают в продукте.

## Из чего собираются

Из компонентов ДС: классы `ds-*`, токены `--ds-*`, состояния из системы. Макет задаёт структуру и тексты, внешний вид задаёт ДС. Правила и разбор частых ошибок — [`../дизайн-система/сборка-из-ДС.md`](../дизайн-система/сборка-из-ДС.md).

Мелкие операции (поправить значение, обновить базу, предложить правку) — [`../03-рецепты/`](../03-рецепты/).

## Как показываем

- **Живым примером, который можно нажимать.** Заказчик щёлкает по кнопкам и переключает состояния — а не читает таблицу с описанием того, как это могло бы работать.
- **Разными панелями на разные режимы.** Если сценарий зависит от роли или состояния (например, заказы разных цехов), на странице делается панель на каждый вариант: так видно разницу, а не приходится верить на слово.
- **Правки — сначала в панели варианта, потом на общем стенде.** Так прототип не расходится сам с собой.

## На что смотрим перед показом

1. Каждый блок собран из компонентов ДС, самодельных стилей нет — кроме обвязки раскладки.
2. Состояния взяты из системы, а не придуманы.
3. Больше одного атома — ищи групповой компонент ДС (кнопки — `ds-btn-group`, чипы — `ds-chips-group`), зазор — токеном группы; если группового компонента нет — между элементами всё равно обязателен отступ.
4. Каждая правка поверх ДС помечена комментарием `/* косяк ДС: … */` и, если это реальный пробел, попала в список замечаний.
5. Страница открывается и нажимается без ошибок; мобильный режим проверен отдельно, если он есть в сценарии.
6. Договорённости, прозвучавшие на показе, записаны в [`../06-решения/`](../06-решения/).
7. Демо-контент шаблона удалён: на странице остался только свой контент прототипа (в селекте «Экраны» — только экраны юзера, без демо-страниц и чужих экранов).
8. Фильтр таблицы стоит в полосе таблицы (header table actions), а не в шапке страницы; справа в полосе — только кнопки и иконки действий (селект — не кнопка; элемент не выше высоты полосы — 36).
9. Select container: «Title select» и «Поиск» по умолчанию не выводим — инпут M → «Title select» нет, S → показываем; поиск — только если значений больше 12 (заказчик, 16.10.2026).
10. Всё, что есть в примере, работает: диалог открывается/закрывается (крестик, Esc, кнопка, клик по затемнению), скролл прокручивается, ползунок Scroll перетаскивается (заказчик, 19.10.2026).
11. Для всех демо-страниц компонентов обязательно смотреть слои и настройки в Figma — дерево слоёв + Properties (вариант/размер/состояние/слоты/вложенные инстансы/скрытые слои); вложенные инстансы собираем компонентами ДС (заказчик, 19.10.2026).
12. Колонка действий строки фиксируется (sticky к правому краю) только при наведении/фокусе строки; в покое — обычная, без фона, тени и разделителя. При фиксации фон = фон строки (#F5F5F5; выбранная — Accent/5 #F8F9FC). Правило `background:transparent` у ячейки при наведении не должно снимать фон у колонки действий (заказчик, 19.10.2026: «фикс только при наведении, а не всегда»).
13. Ширины колонок таблиц — по самому длинному в колонке (дефолт для всех таблиц): max(шапка: текст + 8 + иконка сортировки 20; контент: значение/иконки + паддинги 16), фиксированная без `flex-grow`; гибкая — одна колонка; лишнего запаса справа нет. У дат/статусов ширину задаёт шапка; колонка действий — 2×28 + 4 + 16 = 76 (заказчик, 19.10.2026: «По всем таблицам так… Это условно дефолтное правило»).
14. Карточка формы — на всю ширину контента, поля внутри — смысловыми группами с заголовками, сетка 2 колонки с зазором 16 (заказчик, 20.10.2026: «расширь форму до конца на всю ширину» + «как в баннерах мы делали — разбей форму на группы по смыслу»; правило 19.10 про фикс 720 px отменено).
15. Сайдбар при старте — свёрнут: только рейл 52 px, панель раздела (L2) не открыта; раздел открывается кликом по иконке (заказчик, 19.10.2026: «По умолчанию панель сайдбар всегда в скрытом состоянии слева»).
16. Разделители строк таблиц — у каждой строки нижняя линия 1px #E0E0E0; нельзя снимать внутри Expansion panel и обёрток (`border-bottom: 0` у строк запрещён) — заказчик, 19.10.2026: «Где у строчек тут разделитель???»
17. Полоса действий (`app-table-header-actions`) → таблица — 8 px, и это правило действует ВЕЗДЕ; поиск и инструменты таблицы — тоже с шагом 8 до полосы/таблицы; 16 — только от навигации (табы) до табличного блока (заказчик, 19.10.2026: «Между хедер табле актион и таблицей отступ 8!! … не только на этой странице — это вообще везде так»).
18. Свой счётчик (не компонент Badge) — полностью как соседний текст: family, кегль, вес, интерлиньяж и цвет наследуются от текста, рядом с которым стоит (в табе — шрифт и цвет таба, в строке — шрифт и цвет названия); отступ — `gap` контейнера, без своих margin (заказчик, 19.10.2026: «Каунтер равняется шрифту рядом с которым находится! … Это ко всему относится, если ты ставишь свой каунтер, а не компонент бейдж» + «всё одинаковое с текстом с которым находится»).
19. Состав (баннеры группы, блюда) выбирается чекбоксами в таблице, где показан ВЕСЬ справочник: чекбокс = «входит», строки состава — первыми (номер/интервал/drag), остальные — ниже с «—»; поиск и тумблер «Показать выбранные» (`ds-slide-toggle` в слоте «После заголовка» полосы `app-table-header-actions`) фильтруют список; панели и меню «Добавить» не используем (заказчик, 19.10.2026: «Мы можем сразу все вывести и отметить только то что нам нужно???» + «нужен тугл показать выбранное, чтобы сразу отсеять» + «Тугл в хедер табле актион»).
20. Строка-группа в раскрываемом списке (категории в мультиселекте) — раскрыть/свернуть, а не «выбрать всё»: клик по строке в любом месте кроме чекбокса раскрывает группу, выбор всей категории — только чекбоксом (tri-state); клавиатура `Enter`/`Space` — раскрыть/свернуть, `→`/`←` — раскрыть/свернуть; название группы — medium, элементы — regular (решение UX 20.10.2026).
